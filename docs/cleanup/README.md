# Repository-hygiene change (APPLIED)

## What happened
`313d13b` committed **2522 generated files** under
`services/transport/rust-net/target/` — `.exe`, `.pdb`, `.d`, fingerprints and
compiled dependencies. The crate was created after `.gitignore` gained
`services/transport/rust/target/`, so the existing rule did not cover it, and
`git add -A` swept the build output in.

## What has been prepared here
1. **A forward-only ignore rule** in `.gitignore` (uncommitted). Verified against
   `git check-ignore` to shadow no source file: `Cargo.lock`, `Cargo.toml`,
   `src/*.rs` and `tests/socket.rs` all remain tracked.
2. **`rust-net-target-manifest.txt`** — the exact path list, generated by
   `git ls-files`, for review before any index change.
3. **`scripts/check-no-tracked-build-output.sh`** — a check that fails when a
   generated directory is tracked, so this cannot recur silently.

## What was done, on approval
- `git rm -r --cached services/transport/rust-net/target` — 2522 paths removed
  from the index, every file left on disk. `Cargo.toml`, `Cargo.lock`, `src/`
  and `tests/` verified still tracked afterwards.
- The ignore rule, this manifest and the check script committed alongside it.

## What still has NOT been done, deliberately
- No history rewrite.
- **A forward cleanup does not erase the blobs already published.** They stay in
  history and on the remote. Removing them is a separate rewrite task, out of
  scope, and would require force-pushing a shared branch.

## What this fixed
Every `cargo build` in that crate used to mark hundreds of tracked files
modified (587 at the time of applying), and `scripts/deploy.sh`'s clean-tree
guard failed on that noise. It also made the tree impossible to check out on
Windows: `git worktree add` aborted with "Filename too long" on the deep
`target/debug/incremental/...` paths, which is how the 2026-09-14 deploy was
first blocked.

`scripts/check-no-tracked-build-output.sh` is what stops this recurring; run it
in CI.
